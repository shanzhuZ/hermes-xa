# 账号智能分析平台 — 总览与框架设计

> 面向开发者与零基础读者：看完本文，你能知道 **Hermes 是什么**、**Skill / scripts / Java 各管什么**、**改功能去哪改**。  
> 项目根目录：`D:\hermes-xa`（下文简称 **HERMES_HOME**）  
> **文档版本：2026-07-19**（已对齐当前仓库：01～04 + 05 自定义 + 图片管线）

## 一、用一句话说清楚我们在做什么

我们做一个 **密塔式账号智能分析系统**：

1. 前端 / Java 发起任务（`POST /api/collect/start`）
2. Hermes Agent 按对应 **Skill** 调 MCP / 搜索等工具执行
3. **Python Hook（`scripts/db_sink.py`）** 把工具结果入库，并推进 **步骤树**（`collect_phase_steps`）
4. 前端轮询步骤树 + 订阅思考流 SSE，展示进度与终稿

当前落地业务（以代码为准，不再沿用旧「4 类规划名」）：

| # | 前端 `taskType` | 库内 `task_type` | Skill 名 | Python 包 | Java 预建服务 |
|---|-----------------|------------------|----------|-----------|---------------|
| 01 | `collect` | `account_collect` | `account-intelligence-collect` | `scripts/collect_01/` | `CollectTaskCreateService` |
| 02 | `expand` | `account_expand` | `account-expansion` | `scripts/expand_02/` | `ExpandTaskCreateService` |
| 03 | `verify` | `account_verify` | `account-intelligence-verification` | `scripts/verify_03/` | `VerifyTaskCreateService` |
| 04 | `report` | `account_report` | `account-intelligence-report` | `scripts/report_04/` | `ReportTaskCreateService` |
| 05 | `custom` | `account_custom` | `account-intelligence-custom` | `scripts/custom_05/` | `CustomTaskCreateService` |
| — | （独立管线） | 依附已有 `task_id` | `image-asset-analysis` | `scripts/image_pipeline/` | `ImageAssetController` 只读 |

统一启动：

```http
POST /api/collect/start
{ "taskType": "collect|expand|verify|report|custom", "message": "..." }
```

## 二、Hermes 是什么？（小白版）

可以把 Hermes 想成 **「会调用工具的智能助手运行时」**：

```
┌─────────────┐     HTTP/SSE       ┌──────────────────┐
│  Java/前端   │ ───────────────▶ │   Hermes Agent   │
│  :4377       │ ◀─────────────── │  （大脑 + 调度）  │
└─────────────┘                    └────────┬─────────┘
                                            │
              ┌─────────────────────────────┼─────────────────────────────┐
              ▼                             ▼                             ▼
        ┌──────────┐                  ┌──────────┐                  ┌──────────┐
        │  Skill   │                  │   MCP    │                  │  MySQL   │
        │ 业务手册 │                  │ 数据采集 │                  │ + HBase  │
        └──────────┘                  └──────────┘                  └──────────┘
              ▲                             │
              │                      Hook: scripts/db_sink.py
              └───────────── Agent 读 Skill；Hook 写库推步骤 ───────────┘
```

| 概念 | 通俗解释 | 你要改什么 |
|------|----------|------------|
| **Hermes Agent** | 接模型、跑对话、决定调哪个工具 | `config.yaml` 模型地址 |
| **Skill** | 给 Agent 的业务手册（步骤、禁令、输出格式） | `skills/account-intelligence/*/SKILL.md` |
| **MCP** | 真正干活的插件（微博/Twitter/Apify/OCR…） | `mcp/mcp_servers.yaml` |
| **Hook** | 工具调用前后自动跑的脚本 | `config.yaml` hooks + `scripts/db_sink.py` |
| **Java** | 建任务、预插步骤、转发 Gateway、查树/思考流/历史 | `clients/hermes-xa/` |
| **步骤树** | 前端深度模式进度（`collect_phase_steps`） | 01～04 改 `phases.py` + CreateService；05 改 flow API/CLI |

### 3.1 最常改的入口

| 想做什么 | 改哪里 | 改完怎么办 |
|----------|--------|------------|
| 换模型 / API | `config.yaml` → `model` | 重启 Hermes |
| 加/关 MCP | `mcp/mcp_servers.yaml` → `mcp/install.ps1` | `/reload-mcp` |
| 改 01～05 业务步骤话术 | 对应 `skills/.../SKILL.md` + `references/*.yaml` | 新开会话或重装 Skill |
| 改步骤树结构（01～04） | `scripts/*/phases.py` **+** Java `*TaskCreateService` | 重启 Java；旧任务步骤已落库不自动变 |
| 改入库字段映射 | `scripts/collect_01/normalizers/*` | 重跑任务或回放工具输出 |
| 改步骤推进/门禁 | `scripts/*/sink.py`、`gates.py`、`task_store.py` | Hook 立即生效（无需重启 Java） |
| 改自定义流程图 | Skill `flow-contract.yaml` + `custom_05/flow_*` + Java `FlowStep*` | 重启 Java（仅 API）；CLI 即时 |
| 改 Cookie / DB / HBase | `.env` | 重启相关进程 |
| 改对外 HTTP | `clients/hermes-xa/.../controller/*` | 重启 SpringBoot |

### 4.3 各 Skill 职责与修改点

#### 01 `account-intelligence-collect`

- **做什么**：种子主页 →（可选）Maigret 跨平台 → 候选主页 → 文本/图片流比对 → 可信账号 → 发文 → 三节采集报告。
- **禁**：过程写画像；步骤 1～6 乱用 `web_search`；用错 Maigret 工具名。
- **改步骤顺序/铁律**：`SKILL.md`
- **改输出章节/字段细则**：`references/collect-rules.yaml`
- **改真实落库步骤树**：见 `scripts/collect_01/phases.py` + Java `CollectTaskCreateService`

#### 02 `account-expansion`

- **做什么**：从单一种子向外扩建关联账号；输出四节（扩建收集 / 多平台采集 / 核查 / 账号清单）。
- **改规则**：`SKILL.md` + `references/expansion-rules.yaml`
- **改步骤树**：`scripts/expand_02/phases.py` + `ExpandTaskCreateService`

#### 03 `account-intelligence-verification`

- **做什么**：多平台多种子账号，采集主页+发文，双流比对，输出核验结论（无 Maigret 跨平台发现为主路径）。
- **改规则**：`SKILL.md` + `references/collect-rules.yaml`
- **改步骤树**：`scripts/verify_03/phases.py` + `VerifyTaskCreateService`

#### 04 `account-intelligence-report`

- **做什么**：种子 → Maigret → **允许网页检索补候选** → 主页/流/发文 → 分析 → 画像报告（步骤最多、门禁最严）。
- **改规则**：`SKILL.md` + `references/collect-rules.yaml`
- **改步骤树**：`scripts/report_04/phases.py` + `ReportTaskCreateService`
- **改文本解析/门禁**：`scripts/report_04/*_parser.py`、`gates.py`

#### 05 `account-intelligence-custom`

- **做什么**：不限主题；模型先规划再执行；流程图动态写入；可搜索浏览。
- **改执行节奏/铁律**：`SKILL.md`
- **改 flow 契约（upsert/begin/finish）**：`references/flow-contract.yaml`
- **改写库实现**：`scripts/custom_05/flow_store.py` / `flow_cli.py`；Java `FlowStepService`
- **注意**：步骤一致性靠 begin/finish，不是靠 01～04 那种固定 `phases.py`

#### `image-asset-analysis`（独立）

- **做什么**：从已有 profiles/posts 发现图片 → 下载 → HBase → MySQL `collect_images` → 可选回填 OCR/Vision。
- **改用法说明**：`SKILL.md`
- **改管线逻辑**：`scripts/image_pipeline/*`
- **不替代** 01～04 主流程；第一期通常手动：`python -m image_pipeline.run --task-id ...`

## 五、Scripts 详解（`scripts/`）

### 5.0 总入口与公共约定

| 文件 | 功能 | 何时改 |
|------|------|--------|
| **`db_sink.py`** | Hermes Hook 统一入口：读 stdin JSON，按 `task_type` / 意图分发到各业务 `sink.handle_event` | 新业务类型登记；分发优先级 |
| `sync_collect_hooks.py` | 同步/检查 Hook 配置用辅助脚本 | Hook 安装路径变更时 |
| `demo_collect_api.py` | 演示调用 Java collect API | 联调示例 |
| `replay_collect_task.py` | 回放某任务工具输出（调试入库） | 复现 Hook 问题 |
| `backfill_display_records.py` | 回填 `collect_display_records` | 展示层数据补齐 |
| `_diag_*.py` / `_tmp_*.py` | 临时诊断脚本 | **勿当正式产品逻辑**；可删可加 |

**分发顺序（`db_sink.py`）**：`gateway_session_key=task:{id}` → 查库 `task_type` → 否则看 session 活跃任务 → 否则看消息意图 → 默认 collect。

库表迁移：`scripts/sql/001_*.sql` … `012_collect_images.sql`。改表只加新编号迁移，不要改已执行的历史脚本。

环境变量（`.env`）：`HERMES_DB_*`、`HERMES_PERSIST_ENABLED`、`HERMES_HBASE_*` 等。连接封装多数走 `collect_01/config.py` + `collect_01/db.py`。

### 5.1 `collect_01/` — 01 采集（最完整，多被 02/03/04 复用）

| 文件 | 功能 | 改什么时到这里 |
|------|------|----------------|
| **`sink.py`** | Hook 主逻辑：工具前后更新步骤、调 normalizer 入库、步骤收口 | MCP 事件后步骤不对、漏入库、抢跑步骤 |

## 七、框架架构（现行）

### 7.1 分层

```
接入层：前端 → Java :4377 → Hermes Gateway（SSE）
编排层：5 × Skill（+ 图片 Skill）
执行层：MCP / web_search / browser / terminal(flow_cli)
持久层：Hook db_sink → MySQL；图片 → HBase + collect_images
查询层：Java 读库 → 步骤树 / 历史问答 / 图片字节
```

### 7.2 步骤状态双写约定（方案 C）

| 角色 | 允许写什么 |
|------|------------|
| Java `CoarseStepSync` | 粗：`pending/running→running`；少数白名单工具粗 `completed`；Vision/Apify 等禁粗 completed |
| Python Hook `sink` | **细状态真相源**：completed/failed/skipped、message、动态子步骤 |

详见 `docs/思考流与步骤树同步落库实施方案.md`。

### 7.3 核心表（现行）

| 层 | 表 | 作用 |
|----|-----|------|
| 任务 | `hermes_tasks` | `task_type`=account_collect/expand/verify/report/custom |
| 对话 | `hermes_user_dialogues` | user_input / summary / thoughts_final… |
| 工具审计 | `hermes_tool_outputs` | MCP 原始输出 |
| 步骤树 | `collect_phase_steps` | 前端深度模式 |
| 业务 | `collect_profiles` / `collect_posts` / `cross_platform_candidates` / … | 采集结果 |
| 展示 | `collect_display_records` | 步骤详情 UI |
| 图片 | `collect_images` | 索引；字节在 HBase |

完整表设计仍见 [MySQL数据库设计.md](MySQL数据库设计.md)、[MySQL-01账号采集表设计.md](MySQL-01账号采集表设计.md)。

### 7.4 Hook 配置示例

```yaml
hooks:
  - event: pre_llm_call
    command: python D:/hermes-xa/scripts/db_sink.py
  - event: post_tool_call
    command: python D:/hermes-xa/scripts/db_sink.py
  - event: post_llm_call
    command: python D:/hermes-xa/scripts/db_sink.py
hooks_auto_accept: true
```
