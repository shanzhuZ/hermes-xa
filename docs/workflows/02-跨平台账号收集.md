# 02 · 跨平台账号收集

> ⚠️ **存档文档（2026-07-06）**  
> 本流程已 **并入** [01-账号信息采集.md](01-账号信息采集.md) **阶段 3**（用户仅在首步选择「是否跨平台」后自动执行）。  
> 以下内容仅供历史参考，请以 01 为准。

> **交互模式**：密塔 AI 深度模式 —— 在已知一个或多个平台账号的前提下，**发现、检索、采集**同一自然人在其他平台的账号。  
> **定位**：从单点账号扩展到**跨平台账号图谱**，为核查与多模态分析提供更完整画像。

---

## 一、业务目标

基于已有账号线索（昵称、头像、简介、外链、手机号/邮箱碎片等），在多个社交平台中**检索、匹配、去重**，形成「一人多号」的账号候选列表与图谱，并按用户确认的范围执行采集。

| 产出 | 说明 |
|------|------|
| 候选账号列表 | 各平台疑似同一人账号，带匹配置信度与匹配依据 |
| 跨平台账号图谱 | `entity_id` → 多平台 `account` 映射（含种子账号） |
| 已采集数据 | 对选定账号按 01 流程或简化条件采集 |

> **说明**：本阶段**不做逐条人工确认候选**（原确认点 C、D 已取消），检索结果直接输出；是否为「本人真实账号」交由 **03 账号核查** 批量判定。

---

## 二、触发条件

- 从 **01 账号信息采集** 确认点 E 跳转而来
- 用户直接指令：「查一下这个人在其他平台有没有账号」
- 从 **03 账号核查** 需要补充跨平台线索

**前置输入**（至少一项）：

- 种子平台 + 账号（如 微博 @某某）
- 或 01 阶段已入库的 `question_id` / `account_bundle`

---

## 三、深度模式交互流程

```
输入种子账号（来自 01 或用户直接提供）
    │
    ▼
【确认点 A】要在哪些平台搜索？
    ├─ 全平台（已接入 MCP 的）
    ├─ 用户勾选平台子集
    └─ 仅指定 1～2 个平台
              │
              ▼
【确认点 B】匹配策略与线索来源？
    ├─ 用户名/昵称相似度
    ├─ 头像同源 / 相似
    ├─ 简介、外链、邮箱、手机号
    ├─ Maigret 类用户名枚举
    └─ 组合策略（推荐）
              │
              ▼
    ┌─ 执行跨平台检索（系统默认深度与上限）─┐
    └──────────────────────────────────────┘
              │
              ▼
    展示检索结果列表（只读，无需逐条确认）
              │
              ▼
【确认点 C】下一步操作？
    ├─ 对全部或部分候选账号发起采集 → 复用 01 的时间/数量确认
    ├─ 仅保存图谱与候选列表
    ├─ 将候选列表送入 03 账号核查（批量判定是否本人）
    └─ 结束
```

## 四、各确认点详细说明

### 确认点 A · 目标平台范围

**系统提示示例**：

> 种子账号：**微博 @某某**  
> 请在以下平台搜索疑似同一人的账号（可多选）：  
> - [ ] 微信（搜一搜 / 公众号）  
> - [ ] B站  
> - [ ] 抖音（待接入）  
> - [ ] Twitter/X  
> - [ ] YouTube  
> - [ ] 知乎（待接入）  
> - [ ] 全选已接入平台  

---

### 确认点 B · 匹配策略

| 策略 | 说明 | 适用场景 |
|------|------|----------|
| 昵称匹配 | 编辑距离、同名检索 | 各平台昵称一致或近似 |
| 头像比对 | 感知哈希 / 视觉相似 | 头像复用、换皮小号 |
| 简介/外链 | 提取 URL、邮箱、@ 引用 | 博主留联系方式 |
| 用户名枚举 | Maigret 等扫全平台同名 | 网名统一的用户 |
| 内容交叉 | 同一事件发文时间线吻合 | 舆情关联账号 |

**系统追问**：

> 推荐组合：**昵称 + 用户名枚举 + 简介外链**。是否采用？  
> [1] 采用推荐  [2] 自定义勾选  

---

### 系统默认检索参数（不再向用户确认）

| 参数 | 默认值 | 说明 |
|------|--------|------|
| 每平台候选上限 | 5 | 超出则按置信度截断 |
| 最低展示置信度 | 0.6 | 低于阈值写入弱线索区，不进入主列表 |
| 是否拉取候选主页 | 否 | 仅检索元数据；采集走 01 或确认点 C |

---

### 检索结果展示（只读）

**展示表格示例**：

| # | 平台 | 账号 | 置信度 | 主要依据 |
|---|------|------|--------|----------|
| 1 | B站 | 某某Official | 0.92 | 昵称+简介相同外链 |
| 2 | 微信 | 公众号「某某说」 | 0.78 | 头像相似+关键词 |
| 3 | Twitter | @moumou_xx | 0.45 | 仅昵称部分匹配 |

> 以上为系统自动检索结果。是否本人真实账号，请在 **03 账号核查** 中批量判定。

---

### 确认点 C · 采集与下一步

| 选项 | 后续 |
|------|------|
| 对候选账号执行采集 | 勾选账号子集 → 进入 01 的时间/数量确认 |
| 仅保存图谱 | 输出 `cross_platform_map.json`，结束 |
| 进入账号核查 | → 03，携带种子 + 全部候选账号列表 |
| 进入多模态分析 | → 04（需先有采集数据） |

## 八、异常与边界

- **多种子冲突**：多个种子账号置信度相近时，要求用户指定主账号
- **无候选**：提示扩大平台范围或调整匹配策略
- **同名非同人**：不在本阶段裁决，统一交 03 核查
- **境外平台不可达**：标注网络限制，跳过或走代理策略（配置项）
