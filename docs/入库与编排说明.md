# 01 账号采集 — 入库脚本说明

> 最后更新：2026-07-07  
> 主路径：**Hermes Hook**（`hermes chat` + Skill），Workflow 编排器已移除。

---

## 1. 架构总览

```
用户消息 (Skill 意图)
    ↓
Hermes Agent 调用 MCP 工具
    ↓
Hook: scripts/db_sink.py → collect_01/sink.py
    ├─ pre_llm_call    → 建任务、step1 running
    ├─ post_tool_call  → 写 tool_outputs、normalizer、业务表、步骤推进
    └─ on_session_end  → finalize_task
    ↓
MySQL (hermes-xa)
```

**原则**：MCP 只拉数据；流程在 Skill；**入库与步骤状态集中在 `scripts/collect_01/`**。

| 配置项 | 位置 |
|--------|------|
| Hook 注册 | `config.yaml` → `hooks` → `D:/hermes-xa/scripts/db_sink.py` |
| 数据库 | `.env` → `HERMES_DB_*`、`HERMES_PERSIST_ENABLED` |
| 日志 | `{HERMES_HOME}/logs/collect_01_sink.log` |

## 2. 文件职责

```
scripts/
├── db_sink.py                 # Hook 入口；补设 HERMES_HOME；转调 sink.main
├── replay_collect_task.py     # 从 hermes_tool_outputs 重放补库（调 sink 内部函数）
└── collect_01/
    ├── sink.py                # ★ 事件编排：任务解析、步骤推进、调度 normalizer
    ├── task_store.py          # ★ 任务/步骤/业务表写入门面
    ├── gates.py               # 步骤门禁（查库，不信模型口头进度）
    ├── phases.py              # 步骤树定义、工具→步骤映射
    ├── config.py              # HERMES_HOME、.env、MySQL 配置
    ├── db.py                  # pymysql 连接、事务、upsert
    └── normalizers/
        ├── registry.py        # tool_name → handler 路由
        ├── base.py            # JSON 解包、字段清洗
        ├── twitter.py / youtube.py / maigret.py / apify.py
        └── (weibo 等尚未注册)
```

### 2.1 `sink.py` — Hook 事件处理

| 事件 | 函数 | 行为 |
|------|------|------|
| `pre_llm_call` | `_on_pre_llm` | 识别采集意图 → `ensure_task`；`step1_seed=running` |
| `post_tool_call` | `_on_post_tool` | 主路径：写库 + 步骤推进（见 §4） |
| `post_llm_call` / `on_session_end` | `_on_turn_end` | `finalize_task`（任务 completed、汇总表） |

**模块级状态**（进程内有效，Hermes 重启后清空）：

- `_SEEN_TOOL_CALLS`：按 `tool_call_id` 防重放
- `_LAST_APIFY_HINT`：最近一次 Apify Actor，供 `get_dataset_items` 推断平台

### 2.2 `task_store.py` — 写库门面

| 方法 | 写入表 | 说明 |
|------|--------|------|
| `ensure_task` | `hermes_tasks`, `collect_phase_steps`, `hermes_user_dialogues` | 解析种子平台/handle、是否跨平台 |
| `save_tool_output` | `hermes_tool_outputs` | 原始工具输出存档 |
| `save_profile_row` | `collect_profiles` | 主页资料 |
| `save_candidate_rows` | `cross_platform_candidates` | Maigret 候选 |
| `save_post_rows` | `collect_posts` | 发文 |
| `build_streams_from_profile` | `collect_identity_streams` | 从 profile 拆文本/图片流（**不写步骤状态**） |
| `run_text_compare` | `collect_identity_streams.validation_*` | 规则文本比对 |
| `run_validated_accounts` | `collect_validated_accounts` | 步骤五收敛 |
| `set_step_status` | `collect_phase_steps` + `hermes_tasks.current_phase` | 步骤状态机 |
| `finalize_task` | `collect_task_summaries`, `hermes_tasks` | 会话结束收口 |

### 2.3 `normalizers/` — MCP JSON → 业务行

`dispatch(tool_name, raw, ctx)` 返回统一结构：

```python
{"profiles": [...], "posts": [...], "candidates": [...], "platforms": [...]}
```

未注册的工具返回空列表，**不会报错**，业务表无写入。

### 2.4 `replay_collect_task.py`

按 `hermes_tool_outputs` 时间序重放，复用 `sink` 的 `_persist_normalized`、`_update_steps_after_tool`、`_maybe_advance_pipeline`。用于 Hook 漏写后的补库。

## 3. 步骤定义（`phases.py`）

| step_key | UI 标题 | order | current_phase |
|----------|---------|-------|---------------|
| `step1_seed` | 步骤一：种子账号资料采集 | 10 | `resolve_seed` |
| `step2_cross_platform` | 步骤二：跨平台账号收集 | 20 | `cross_platform` |
| `step3_profiles` | 步骤三：候选主页采集 | 30 | `cross_platform` |
| `step3_streams` | **步骤四**：文本流与图片流拆分 | 40 | `stream_gen` |
| `step4_text_compare` | 步骤四：文本流对比 | 41 | `stream_validate` |
| `step4_image_compare` | 步骤四：图片流对比 | 42 | `stream_validate` |
| `step5_validated` | 步骤五：可信账号收敛 | 50 | `account_finalize` |
| `step6_posts` | 步骤六：分平台发文采集 | 60 | `collect` |
| `step6_post_{platform}` | 动态子步骤 | 610+ | `collect` |

> **命名陷阱**：`step3_streams` 的 key 带 `3`，标题却是「步骤四」。前端若按 `step_key` 排序会与用户心智不一致，应按 `step_order` 或 `title` 展示。

### 工具 → 主步骤映射（`TOOL_PRIMARY_STEP`）

| 工具 | 步骤 |
|------|------|
| `mcp_twitter_get_user_info` | step1_seed |
| `mcp_maigret_collect_accounts` | step2_cross_platform |
| `mcp_youtube_get_channel_stats`、Apify 系列、`get_dataset_items` | step3_profiles |
| `mcp_ocr_perform_ocr`、`mcp_vision_analyze` | step4_image_compare |
| `mcp_twitter_get_user_tweets` 等发文工具 | step6_posts（子步骤按平台） |

## 4. 步骤状态流转（Hook 实际逻辑）

### 4.1 状态写入规则

`set_step_status` 要点：

- `running`：`started_at` 仅首次写入；从终态回退时清空 `finished_at`
- `completed` / `failed` / `skipped`：`finished_at = COALESCE(finished_at, NOW())`，**终态时间只写一次**
- 每次更新步骤会同步 `hermes_tasks.current_phase = step_phase(step_key)`

### 4.2 各步骤何时变化

| 步骤 | running | completed / skipped |
|------|---------|---------------------|
| step1 | `pre_llm` 或首次种子工具 | `mcp_twitter_get_user_info` 成功 |
| step2 | **Maigret `post_tool` 入口**（`TOOL_PRIMARY_STEP`） | Maigret 成功；非跨平台建任务时直接 `skipped` |
| step3_profiles | Apify/YouTube 等 profile 工具 | **首次 OCR/Vision** 时 `_enter_step4` 收口 |
| step3_streams | 首次 OCR/Vision 时 `running` | 图片比对完成且文本比对后 `completed` |
| step4_text | 图片比对 `completed` 后 `running` | `run_text_compare` |
| step4_image | 首次 OCR/Vision 时 `running` | **每个头像至少 1 次 OCR/Vision 成功** 后 `completed` |
| step5 | 文本比对完成后 | `run_validated_accounts`（须 `can_advance_to_step45` 通过） |
| step6 | — | `finalize_task`（有发文则 completed，否则 pending） |

### 4.3 步骤四/五门禁（`gates.can_advance_to_step45`）

推进 `run_text_compare` / `run_validated_accounts` 前须满足：

1. `step1_seed = completed`
2. 跨平台任务：`step2_cross_platform = completed`；非跨平台：`skipped`
3. `step3_profiles = completed`（依赖 Agent 调用 OCR/Vision 才会收口）

### 4.4 数据流（profile → 流 → 比对 → 收敛）

```
profile 入库 (step1/3)
    → build_streams_from_profile → collect_identity_streams（静默，不改步骤）
OCR/Vision 成功（须每个头像图片流各至少 1 次）
    → step4_image_compare completed
    → _advance_text_and_validate
        → step4_text_compare running → completed
        → step3_streams completed
        → step5_validated completed
```

## 5. 任务解析（`_resolve_task_id`）

优先级：

1. `extra.task_id` 且库中存在
2. `session_id` 查最近 `account_collect` 任务
3. 用户消息匹配采集意图 → `ensure_task`
4. 首个 MCP 调用且 `tool_input` 含 handle → 自动建任务

## 6. 已知问题与漏洞

### 6.1 已修复（2026-07-07）

| 现象 | 根因 | 修复 |
|------|------|------|
| Maigret 运行时 UI 显示「步骤四：流拆分」running | step1 写 profile 时 `build_streams_from_profile` 误标 `step3_streams=running`；Maigret 被排除在 step2 running 逻辑外 | 流拆分不写步骤；Maigret 走统一 `TOOL_PRIMARY_STEP` 标 step2 running |

### 6.2 仍存在的风险

| 类别 | 问题 | 影响 | 建议 |
|------|------|------|------|
| **步骤命名** | `step3_streams` 标题为「步骤四」 | 前端/日志易误解 | 统一 key 与 title，或前端只认 `step_order` |
| **步骤推进分散** | 逻辑分布在 `sink._update_steps_after_tool`、`_maybe_advance_pipeline`、`_mark_step3_closed`、`task_store` 多处 | 难维护、replay 易漂移 | 收敛到 `steps.py` 或 `task_store.advance_after_tool()` |
| **门禁未统一** | `check_step1_seed` / `check_step2_maigret` 仅编排器时代使用，Hook 未调用 | step 标 completed 但库无数据时无法拦截 | completed 前调用 gate，或改为「只信库状态、步骤仅展示」 |
| **防重无效** | `_SEEN_TOOL_CALLS` 进程级；Hermes 重启或子进程新建会丢 | 极端情况重复入库 | 依赖 DB `tool_call_id` UNIQUE（已有 ON DUPLICATE KEY） |
| **phase 覆盖** | 任意子步骤 `set_step_status` 都会 `set_task_phase` | 并行工具时 `current_phase` 可能被后写工具覆盖 | 仅在大步骤切换时更新 phase，或取最大 `step_order` 的 running 步骤 |
| **normalizer 缺口** | `mcp_weibo_get_profile` 等在 `phases` 有映射，`registry` 无 handler | 微博 profile/发文不入库 | 补 `weibo.py` 并注册 |
| **OCR 依赖** | step3 须 OCR/Vision 才 completed，gate 才放行 step4/5 | Agent 跳过 OCR 则流水线卡住 | Skill 强约束或 gate 改为「有 N 个 profile 即可」 |
| **finalize 过宽** | `on_session_end` 一律 `hermes_tasks.status=completed` | 步骤未完成任务也显示完成 | 按步骤终态聚合决定任务 status |
| **编码** | Windows 子进程 stdin/stdout 可能 GBK | Hook 解析失败、漏写 `tool_outputs` | sink 已双解码；MCP 侧避免超大 payload |
| **replay 耦合** | `replay_collect_task` import `sink` 私有函数 | sink 重构易破 replay | 抽 `pipeline.py` 公共 API |
| **跨平台默认值** | `ensure_task` 默认 `cross_platform=1`，仅显式「不跨平台」才为 0 | 用户未说明时总跑 Maigret | 与 Skill 文案对齐或默认 0 |
| **vision 工具名** | `_STEP4_TOOLS` 含 `vision_analyze`，registry 无 | 非 `mcp_` 前缀工具不落库 | 确认 Hermes 实际 tool_name 并注册 |

### 6.3 Maigret 偶发未入库

日志有 `maigret post_tool` 但 `hermes_tool_outputs` 无记录时，多为写库前异常或 `task_id` 解析失败。排查：

```sql
SELECT tool_name, status, executed_at FROM hermes_tool_outputs WHERE task_id='...' ORDER BY id;
SELECT step_key, status, message FROM collect_phase_steps WHERE task_id='...' ORDER BY step_order;
```

补库：`python scripts/replay_collect_task.py <task_id>`

## 7. 精简建议（按优先级）

### P0 — 低风险、立刻可做

1. **单入口推进步骤**：新增 `collect_01/pipeline.py`，把 `sink` 里 `_update_steps_after_tool`、Maigret completed、post 子步骤、`_maybe_advance_pipeline` 合成 `advance_after_tool(store, task_id, tool_name, result_data, status)`；`sink` 与 `replay` 只调这一处。
2. **completed 前查库**：step1/step2 标 completed 时调用 `gates.check_step1_seed` / `check_step2_maigret`，失败则保持 `running` 并写 message。
3. **补 weibo normalizer**：与 twitter/youtube 同模式注册到 `registry.py`。

### P1 — 结构优化

4. **`set_step_status` 不再每次改 `current_phase`**：新增 `sync_task_phase(task_id)`，在 pipeline 末尾按最高进行中步骤计算。
5. **`build_streams_from_profile` 重命名**为 `upsert_identity_streams`，避免与「步骤四」混淆。
6. **`finalize_task` 区分** `completed` / `partial`：例如 step5 未完成则 `status=running` 或 `partial`。

### P2 — 可暂缓

7. 合并 `gates.get_step_status` 与 `task_store` 查询，避免重复 SQL。
8. `phases.py` 中 `step3_streams` 改名为 `step4_streams`（需 DB 迁移 + 前端联调）。
9. 删除未使用的 `init_phase_steps`（与 `ensure_task` 重复）。
