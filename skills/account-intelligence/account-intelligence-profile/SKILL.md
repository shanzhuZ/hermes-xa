# 02 · 账号深度画像报告（account-intelligence-profile）

> **与 01 采集互斥**：用户只说「采集」「跨平台采集」时 **不要** 加载本 Skill。  
> 仅当用户明确要求「深度画像」「六节报告」「调查分析」时才启用。

## 概述

在 `account-intelligence-collect` 采集完**原始数据**后，本 skill 负责写一份**纵深中文报告**——不重复原始数据本身，而是从采集信息中做推断、交叉分析、隐私风险评估。

**前置条件**：必须先完成 `account-intelligence-collect` 采集（或已有等效的原始数据：账号资料 + 历史发文列表）。

**输出原则**：每条结论必须有采集数据支撑，不编造、不猜测。无法推断的写「无足够数据」。

## 启用方式

```text
你现在有原始数据，对 [username] 做深度画像报告。
```

## 报告模板（6 模块）

### 模块一：账号画像

描述账号的面貌和定位。

- **身份标签**：基于简介/keywords 概括（如「教育博主」「AI 研究者」「生活记录」）
- **活跃平台**：maiqret 扫描到的平台列表
- **公开信息分析**：昵称/简介/认证/粉丝量的特征解读（是否常见伪装名、简介是否一致、认证说明什么）
- **Unique ID / 关联线索**：多个平台间发现的一致性关联（相同 handle、重复的介绍、镜像头像）

### 模块二：内容洞察

分析账号的主要内容领域、发布频率与热度趋势。

- **主要话题**：按发文内容频次归纳（如政治/科技/个人生活/工具转发）
- **发布频率**：近 90 天发文数量 + 密度估算（日均 X 条）
- **互动特征**：高热度内容类型（点赞峰值的共同特征）、低热度内容类型
- **语言风格**：正式/口语化、中文/英文混合、情感倾向

### 模块三：行为模式

描述账号的发布习惯、时间规律、互动对象与信息传播倾向。

- **活跃时间段**：统计发文时间是否有固定规律（如需检查 break，说明「未采集时间戳，无法分析」——不编造）
- **转发 vs 原创**：估算 原创/转发 比（从发文列表判断）
- **他人互动**：是否有特定 @ 对象或固定互动的账号
- **冷启动证据**：近期突然高频率发布 / 账号注册时间与首次发文间隔

### 模块四：数字足迹

maiqret 扫描 + 手收集到的关联足迹。

- **平台覆盖数**：collect_accounts 返回的平台数（即使只采集了种子也列出）
- **同一人跨平台连接**：确认为同一人的各平台账号
- **隐私风险点**：自曝位置信息、真实姓名、联系方式、工作单位、家人线索
- **数据泄露线索**：邮箱/手机/地址/真实姓名出现在简介、发文或用户名中

### 模块五：风险与隐私暴露

基于以上数据分析隐私暴露程度。

- **暴露等级**（低/中/高）：从数字足迹中提取
- **具体暴露项**：逐一列出（如「真实姓名『李 XX』出现在 2026-01-15 的发文中」）
- **社交工程风险**：是否有足量信息做身份冒充/密码恢复攻击
- **建议**：如果暴露程度高，建议该用户做哪些隐私保护动作（可选）

### 模块六：综合评估

1~2 段总结。

- 这个账号的身份明确程度（模糊/可确认/明确指向自然人）
- 主要内容目的（自我表达/信息传播/商业推广/其他）
- 最值得关注/危险的几点

## 执行流程

### 1. 加载原始数据

确认已有采集结果。如果是当前对话中刚采集完，直接用对话里的数据。否则手动找。

需要的数据：

- 账号资料（每个平台的 profile：昵称、简介、粉丝、认证、头衔）
- 发文列表（时间、正文摘要、互动量、链接）
- maigret collect_accounts 或 search_username 的结果

### 2. 按 6 模块输出

用中文自然段，不要 JSON，不要纯 Markdown 表格。每个模块用二级标题（##）分隔。

每个模块里：

- 有结论必有数据来源
- 没有数据就说「无足够数据」/「采集未覆盖」

### 3. 示例片段

```
## 账号画像

- **身份标签**：科技内容创作者、加密货币与 AI 交叉领域博主
- **活跃平台**：Twitter（主阵地）、知乎、GitHub
- **公开信息分析**：三个平台均使用同一 handle 和相近简介，说明无隐私意识或无隐藏意图……

## 内容洞察

主要话题集中在 加密货币/去中心化 和 AI 工具评测。近 90 天发文约 240+ 条（日均 2.7 条）。高热度内容集中在「XX 项目分析」类，平均点赞 80+。
```

### 4. 语言

优先中文。如果用户用其他语言输入，则跟随用户。**如果没有用户语言偏好且原始数据是中文，使用中文。**

## 陷阱

- ❌ **不要强行凑模块**：如果一个模块完全无数据，直接写「无足够数据」，不编造内容
- ❌ **不要重复原始数据**：不要完整 dump 发文列表或 profile JSON，那是 account-intelligence-collect 的阶段
- ❌ **不要做假设**：不要写「可能是 X」「看起来像 Y」，结论必须有数据支撑
- ❌ **不要叫「Doxxing」** 等敏感词，用户约定用「人物画像」「画像报告」或「Profile Report」
- ✅ 如果数据量太少（如只采到 1 条推文），直接说数据不足以做完整报告并给出能说的结论
